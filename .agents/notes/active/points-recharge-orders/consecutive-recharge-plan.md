# 连续充值赠送与新 Docker 部署

时间：2026-09-30T20:05:00+08:00；本次变更集 `consecutive-recharge-20260930`，追加到既有充值范围。

## 需求与验收

- 优惠类型新增连续充值赠送，按用户、稳定套餐 ID、Asia/Shanghai 成功入账日期统计，不按渠道或套餐版本重新开始；断一天从第 1 天重新计算。
- 设置最大天数和每一天的赠送积分，可设 0；赠送不是减免金额，连续活动下每次实付为套餐定价。
- 用户确认赠送频率可选每天首笔（默认）或每单赠送；同日重复充值不增加天数。用户同时确认超过最大天数后持续按最后一天额度赠送。
- 四渠道共用服务端验真结算；取消/失败/待付不算成功，退款不恢复或清除成功事实。重复回调、并发与事务失败不重复发分或推进天数。
- 只更新 billing 业务页面和应用 API；不修改 Vben 共享框架、登录、布局或其他应用。
- 新 Docker 部署当前开发环境，独立配置、密钥与数据卷；现有其他容器保留。真实支付渠道继续沿用已有配置门槛。

## 方案与计划

1. 新增用户套餐连续状态表；读取缺少状态的旧用户时，按不可变订单 settled_at 和 paid_ledger_id 回放历史连续日期。成功结算在既有用户锁下更新，报价只读。
2. 活动规则保存在现有不可变 JSONB 版本中。连续活动属于条件赠分，报价估计与结算重新计算；预算复用现有严格额度，基础积分和套餐赠分仍兑现。
3. 增加 DTO/Swagger、运营最大天数/逐日额度/频率表单、充值报价天数提示；当连续活动参与当前订单时排除现金减免，避免其他现金活动静默改价。
4. 单元测试覆盖时间/规则；隔离 PostgreSQL 覆盖历史回放、结算天数、频率、并发、预算和失败回滚；迁移按 Atlas Skill 做旧数据保留、往返和实体差异检查。
5. 构建前后端 Docker，迁移/初始化/健康检查，更新当前文档和验收记录。
