# 验收矩阵

以下为计划，尚未运行；业务以最终确认方案为准。

## 账本与权限

| 场景 | 验收结果 |
| --- | --- |
| 余额100，200并发各扣1 | 恰好100成功，余额0，100条有效流水，无负值 |
| 100个同键请求扣10 | 只扣10；同键不同请求冲突 |
| 流水插入失败/事务中进程故障 | 余额/批次/订单一起回滚 |
| 冻结/捕获/解冻/冲正重复 | 不超原凭证，不重复释放，不挪用别的充值批次 |
| 直接UPDATE/DELETE历史账本 | 普通应用路径拒绝；保留DB owner运维边界说明 |
| bigint越过JS安全整数 | JSON与计算无精度丢失，超范围拒绝 |
| 普通用户/仅列表权限 | 不可加减分、越权读单或退款 |
| 软删除/禁用用户 | 新单拒绝，历史保留，已有真实支付/退款不丢失 |

## 套餐、首单和优惠

| 场景 | 验收结果 |
| --- | --- |
| 日限量10，100人并发抢 | 有效预占+成功<=10 |
| 总限量/日限量/用户限购/券预算同时竞争 | 任一不足整体回滚，无其他资源泄漏 |
| null、0、当日调低、版本更新 | 不限/禁购语义正确；不可低于占用；版本不清销量 |
| 四渠道并发完成同一用户充值 | 全局用户首单一次、同结算日首单一次；退款不恢复 |
| 第一单未获首单赠分 | 仍消耗首单事实，后续不补领 |
| 满减/券/折扣/赠分竞争 | 互斥、取整、最低金额、预算、确定排序符合方案 |
| 报价后规则/库存变化 | 下单重新确认，不静默加价 |
| 午夜/月底/年末/改变展示时区 | 库存日与结算日明确且正确，展示时区不改资格 |
| 内购固定SKU与后台现金券 | 不伪造商店扣款价；渠道不支持能力明确拒绝 |

## 四渠道与故障

| 场景 | 验收结果 |
| --- | --- |
| 同事件100遍/不同事件同交易 | 只履约一次 |
| 回调与主动查单竞争 | 共用结算逻辑，只核销一次 |
| 支付与关单竞争 | 不同时发分和释放库存；未知状态继续追踪 |
| 创建支付超时/响应丢失 | 同商户号查证，不多次收款 |
| 伪签名/金额/币种/商户/app/environment错误 | 无发放，有拒绝审计；合法原始体及回包通过 |
| Apple/Google交易被另一个用户重放 | 不能重复领取或抢走归属 |
| Google PENDING→PURCHASED | pending不发分；购买后发分一次，消费确认可重试且在期限内 |
| Google RTDN重放/撤销、Apple通知乱序/漏发 | 身份验证、主动查询、通知历史恢复，状态不倒退 |
| IAP已入账后确认失败/客户端断网 | 仅补确认，不再发分；客户端恢复通过服务端结果完成交易 |
| IAP延迟付款跨日 | 遵循已确认渠道差异策略；真实付款不被静默丢弃 |
| 原积分已消费但账户另有分 | 主动退款不挪用其他来源 |
| Apple强制退款/Google撤销时已消费 | 记真实退款、回收剩余、记录缺口/限制消费，不负余额 |
| 主动退款成功/失败/未知及重复 | 扣冻结/解冻仅一次，未知不盲目释放 |
| 外部操作成功后worker崩溃 | 租约重领、查单幂等恢复，旧token不能覆盖新任务 |
| Redis中断/数据库死锁或池耗尽 | 无丢账/超卖；有限重试或明确失败，恢复有预留容量 |
| 构造对账差异 | 正确告警，修复带凭证且重复无副作用 |

## 性能与工程

真实PostgreSQL、多连接/进程验证；SQLite/单线程mock不能证明并发正确。隔离测试库白名单保护，不能指向日常或生产库。原子性核验覆盖余额、流水、批次、额度和任务。

初始压测目标（未验证，必须记录硬件、数据库、池、实例配置）：2个API+1个worker，1万用户/100万流水；预热后15分钟1000 RPS，80%查询/15%下单/5%积分写。查询p95<=200ms，本地写p95<=500ms，非预期5xx<0.1%；渠道网络耗时单列。409/售罄/限流不能计为成功吞吐。

单列爆款200并发抢10份、同账户200并发、同交易100并发；报告实际接受TPS、p99、锁等待和拒绝率。正确性违规必须0；可控模拟渠道故障恢复后5分钟清理测试积压。达不到先报告瓶颈，不将开发机结果当生产承诺。

每阶段：聚焦测试→typecheck→lint:check→build，按影响跑用户/权限/setup/发布回归；更新Swagger。迁移用Atlas及隔离库旧数据验证，标记未运行项。四渠道各有契约测试、沙箱联调、签名/证书轮换和恢复证据；真实凭证和外部App缺失时不得把桩测试当联调通过。完成阶段回填证据、文档审查和版本同步。
