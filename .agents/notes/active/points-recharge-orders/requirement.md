## 推荐细化口径

| 项目 | 方案 |
| --- | --- |
| 每日首单 | 每用户、每业务日首笔成功充值，不是平台当天第一单 |
| 用户首单 | 每用户生命周期首笔成功充值，不按套餐或渠道重置 |
| 业务日期 | 固定 Asia/Shanghai，与用户展示时区无关；按日历边界计算 |
| 精度 | 积分、ID、金额用整数与十进制字符串，禁止浮点；微信/支付宝金额CNY分，内购保存渠道币种和原始金额单位 |
| 积分账户 | 可用、冻结两类余额，均不小于0；支持发放、扣减、冻结、核销、解冻和冲正 |
| 积分来源 | 基础积分和赠分分批记账；长期有效，暂不实现到期扣减 |
| 套餐 | 价格、基础/赠送积分、销售时间、上下架、排序、总量、每日量、用户日/累计限购；0不可买，null不限 |
| 一单数量 | 一单一份套餐，不提供批量购买 |
| 优惠 | 直减、折扣、满减、赠分、首单优惠、定向券/公共码、活动预算与互斥规则 |
| 微信/支付宝待付 | 默认15分钟，不跨业务日或所选活动截止；一用户仅一个这类有效待付订单 |
| 退款 | 首期整单；主动退款须回收对应来源基础+赠送积分，已消费则人工处理；渠道强制退款独立记录风险缺口 |
| 用户删除 | 软删除不删除财务历史，回调/退款继续处理真实支付事实 |

用户已确认渠道差异：内购固定商品权益，首单按服务端首次验真入账判定；严格每日限量和站内现金券先用于微信/支付宝，内购参与明确规则的赠分活动。其余建议作为可审查默认值记录，影响资金和权益的未决事项须在相关阶段前明确。

## 参与者与边界

用户查询自己的余额/流水、套餐与报价、订单和退款；运营管理套餐/活动；授权管理员人工调整/冲正；财务审批退款及处理对账差异。系统负责验签、去重、关单、发分、补单、任务恢复与告警。

当前仓库仅后端：提供管理权限、DTO、Swagger和移动端接入契约，不包含Vben页面、iOS/Android客户端工程。内购端到端上线需要外部客户端和商店配置配合。

不提供现金钱包、提现/转账、部分退款、订阅扣款、分账、发票、汇率换汇、真实多租户隔离。现有tenant_id为预留字段，服务端固定1，不接受客户端指定。
