# v2 需求范围（仅规划）

时间：2026-09-18（Asia/Shanghai）。来源：用户要求当前修复初始化数据，并开始规划 Vben mock 没有的生产能力，例如站内信通知。

## 目标

从已验收的 Vben 管理后端扩展为可实际运营的后台基础服务。v2 是产品阶段名，目标发布线为 2.x；本次不实现模块、不建表、不添加未来权限或菜单、不将包版本改为 2.0.0。

现有部门、用户、角色、菜单、附件、上传策略、时区和认证已实现，不计为 v2 新功能。初始化修复单独在当前 patch 交付。未来扩展按真实服务端能力设计，不能把 mock 数组改成数据库表就视为交付。

## 首个闭环：为已有通知 UI 补齐站内信后端

Vben 已有 Notification 弹层和本地演示数据。首期优先复用铃铛、列表与交互，将本地数组操作接入持久化后端；完整消息中心及运营发布是建议扩展，不把已有组件列为从零开发。移除/清空建议只隐藏当前接收者记录，不删除全局消息，具体语义在 M0 冻结。

- 接收者：登录用户，在个人消息中心分页查看自己的通知、详情、未读数量，单条或全部标记已读；支持多设备状态同步和离线后补拉。
- 运营者：显式授权的管理员创建草稿、选择接收对象、发布并查看投递汇总；普通用户角色无发布、管理或查看他人消息的权限。
- 内部业务模块：通过应用服务发送事件通知，使用业务幂等键避免重试重复投递；首期不开放匿名或普通用户任意发送接口。
- 范围：站内通知、系统公告。公告发布时展开当前有效接收用户形成快照；角色或部门随后变化不改变历史接收者，不向后加入者自动补发。
- 内容：首期纯文本标题、正文与受约束的站内跳转目标；不引入任意 HTML、文件附件、外链跳转或富文本清洗体系。
- 发布后内容不可直接编辑，纠错通过新通知；撤回、定时发送、邮件、短信、移动推送、聊天均为后续候选。

## 安全与兼容边界

服务端从身份取接收者 ID，查询详情、标记已读及计数都附带接收者范围；不能只靠前端过滤。个人能力不依赖 system:* 管理权限。后台管理权限逐项授权。保留现有 ResOp、字符串 bigint、timestamptz、Swagger、角色权限缓存和用户会话失效规则。

本仓库仍只交付后端。需给独立 Vben 接入方提供契约、状态与验收说明；现有通知组件由接入工程接上真实接口，新增消息中心页面另行实现，未交付的页面不能提前写入生产菜单。

## 非阻塞建议与实施前决策

上述为可评审的推荐方案。进入开发前需确定最大接收人数、分页/发布配额、消息保留时间及清理周期、停用/删除用户数据处理、是否必须多实例部署，并据此锁定容量验收。首期建议支持指定用户、角色、部门及全体有效用户，部门范围显式选择是否含子部门；发布预览显示实际接收人数，避免误发。
