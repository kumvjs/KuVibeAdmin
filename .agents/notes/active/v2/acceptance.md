# v2 站内信验收草案

以下均为未来验收，当前未执行。

- 接收者 A 不能枚举、查看或标记 B 的通知；普通 user 调用发布和管理接口被拒绝；有编辑权而无发布权的运营者也不能发布。
- 单用户、多角色交叉、部门含子级和全体有效用户发布均去重；发布后角色/部门改变不污染原快照；接收人数与预览/结果可解释。
- 同一业务幂等键重复发送只产生一次逻辑通知；失败事务没有半条消息；批次重试没有重复接收记录。
- 已读操作幂等；全部已读不吞掉截点之后的新通知；多设备同步后计数与数据库一致。
- 离线期间的通知登录后可查询；推送中断、进程重启及重复事件不造成历史丢失或重复 UI 项；HTTP 始终可恢复实际状态。
- 分页在相同时间戳下顺序稳定（时间与 ID 游标）；接收者索引通过查询计划与容量测试核验；规模指标在 M0 冻结后填入。
- 通知正文作为文本展示；跳转目标经过白名单/站内路径校验；响应、日志和推送不泄露非接收者内容。
- 后台通知页和个人消息中心使用真实接口；加载、空态、错误、重试、未读更新通过浏览器验收。
- 迁移 up/down、存量数据保护与回滚演练通过 Atlas 工作流；消息保留清理不会删除其他用户当前有效记录。
- 发布文档准确标明单实例/多实例支持范围、任务积压告警、重试及恢复方法，无未实现菜单或 mock 成功响应。

- 复用上游 Notification 组件，逐项验证 read、makeAll、remove、clear、onClick、viewAll；刷新后状态保持，接口失败不显示虚假成功。
- 移除/清空仅影响当前接收者，另一接收者仍可查看；隐藏后的计数规则在 M0 明确并验证，截点之后新通知不被清空。
- 当前弹层页无未读但其他页存在未读时，铃铛圆点仍正确显示；viewAll 接入真实历史页面；布局铃铛不新增管理菜单。
