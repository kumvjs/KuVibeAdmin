# 初始化脚本防止重复初始化并支持输入重试

时间：2026-09-15T16:31:00+08:00

## 问题与决策

`setup.ts` 原先只按输入用户名检查重复，且无条件覆盖 JWT 和 Refresh Token 密钥。输入长度或密码确认错误会直接结束脚本。

本次属于初始化 CLI 的局部修复，复用当前用户、角色及关联实体，不改变运行时鉴权或数据库结构。启动后通过未软删除的用户、角色和关联检查 `role.code=super`；存在关联用户即提示退出，禁用用户也阻止重复初始化。不可用的 super 角色需恢复并启用，不自动修改角色状态。

密钥通过 dotenv 解析，仅在目标环境文件及进程环境均无非空值时生成；已有值（包括示例占位值）保留。两个密钥完整时不写文件。用户名采用用户要求的 6–100 位，密码保留工作区已调整的 6–128 位。长度、重名和确认失败支持循环重试；数据库和文件操作失败仍作为初始化失败处理。

## 实现与约束

- 提前连接数据库并检查初始化状态，退出时关闭连接；交互结束时关闭 readline。
- 用户与角色创建继续使用现有事务，保留事务内重复用户名及角色状态检查。
- 不修改实际环境文件，不运行真实数据库初始化，不保证多个 setup 进程并发执行的全局互斥。
- 不涉及接口、数据模型、UI 或架构变更；更新 `docs/guide/getting-started.md` 的初始化流程。

- pnpm 版本切换因远端签名获取失败未能运行，验证改用已安装的 `node_modules/.bin` 工具。

## 后续影响

重复执行不会生成额外管理员或轮换现有密钥；已有账号应通过管理流程恢复。初始化前应清空示例密钥或配置正式值。
