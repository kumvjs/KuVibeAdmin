# M7.1 — 系统附件模块设计草案

状态：M7.1 已完成并验证。默认私有、业务明确开放公开图片，当前存储驱动为本地持久卷；已实现策略缓存、上传、鉴权下载、附件管理、审计、业务绑定和安全清理。已替代 M7 的临时图片上传，不改变其他演示接口。

## 模块和存储

- 独立 UploadModule，生产环境可用，沿用现有认证、RBAC、Redis 和 `ResOp`。首批提供本地存储实现，内部存储接口预留对象存储；不同时开发多套驱动。
- 文件存储在公开静态目录之外，使用随机对象 key；业务数据库保存附件 ID，不以 URL 或原始文件名作为存储身份。本地部署多实例需共享持久化存储，否则不能保证跨实例下载。
- 新建附件、上传策略、业务引用表，所有列显式声明数据库类型；不生成迁移、不自动转换或删除旧临时文件。
- 附件记录包含原始名称、扩展名、检测后的 MIME、字节数、校验和、存储驱动/key、上传人、用途、可见性、生命周期状态和审计时间。引用记录包含附件及业务标识，但业务存在性和权限必须由相应业务服务验证，不能信任客户端自报的业务 ID。

## 格式与策略

- 建议首批覆盖 JPEG/PNG/WebP/GIF、PDF、TXT/CSV、DOCX/XLSX/PPTX、ZIP、MP3/MP4；具体开放集合由用途策略选择，并非所有用途默认开放全部格式。
- 策略表管理启停、允许格式、单文件大小、请求总大小/数量、用途、默认可见性及未绑定文件保留期。头像策略可额外限制图片尺寸。默认记录只在初始化时创建，运行时不从环境变量覆盖业务设置。
- 原有 `POST /upload` 保持单个 `file` 契约；数量配置不能暗中把响应改为数组，批量上传应独立定义并测试契约。
- 格式可配置不等于允许任意后缀：只能启用已有可靠验证器的格式。校验扩展名、MIME 和实际内容；Office 容器和纯文本分别验证，不能把 ZIP 魔数当成 Office 检测。宏文档、脚本、可执行文件、HTML/SVG 默认不开放；压缩包不自动解压。
- 流式计数和落盘，不把大文件完整读入内存；超过限制、中断或校验失败应清理本次暂存对象。配置上限还受代理/框架资源上限约束，部署时校验二者兼容，不静默截断配置。
- 类型校验不能保证文件无恶意内容；需保留隔离/扫描状态与扫描接口，未接入杀毒引擎时不得宣称已扫描，生产启用高风险格式前另行评估。

## 缓存规则

- PostgreSQL 为策略事实来源；复用 CacheService/Redis，按用途缓存完整有效策略。命中不读策略表，未命中加载并设置有限 TTL，缺失/禁用策略不能回落为无限制上传。
- 管理操作先提交事务，再失效对应缓存；增加策略版本及锁/条件回填机制，防止旧并发读取在更新后写回陈旧策略。失效失败需告警与重试，TTL 仅作兜底，不能声称跨数据库和 Redis 的操作天然原子。
- 首批避免再叠加各进程的无限期本地缓存。Redis 故障时限流回源；无法取得有效策略则拒绝新上传，不使用宽松默认值放行。
- 一次上传使用开始时取得的策略快照，策略更新影响之后的新请求。缓存具体 TTL、生效窗口及并发更新行为须在实现测试中明确。
- 仅缓存配置不代表可以缓存并复用所有下载授权；附件引用和业务权限仍须按当前状态校验。

## 私有与公开访问

- 私有附件指不能通过永久公开 URL 匿名读取的文件，例如合同、报表、身份证明。建议首批支持且默认私有，不额外引入一套复杂分享 ACL。
- 未绑定文件限上传人及有专门权限的附件管理员访问；绑定后交由业务授权判断，上传人身份不应永久绕过后续业务权限。未知业务类型默认拒绝访问。
- 公开图片仅供业务明确批准的场景，例如头像。上传者不能仅凭请求中的 `public` 字段发布任意文件；公开属性不应自动继承新配置，也不应悄悄改变历史附件可见性。
- 首批私有下载走现有登录态及对象权限检查，返回文件流，不暴露物理路径。普通文件强制 attachment、安全文件名和 nosniff；私有响应禁止共享缓存，日志不记录令牌。
- Vben 的 `url` 字段保留需区分公开图片地址和鉴权下载地址；后者不能当作匿名图片 URL。浏览器需用携带认证的请求获取 Blob，不把 Access Token 塞入 URL。公开头像是有意披露，后续撤销也不能收回已下载副本。

## 管理与生命周期

- 提供按名称、格式、用途、上传人、时间、状态过滤的分页列表，以及权限隔离的详情、下载、删除、策略管理和操作审计。
- 上传完成不等于业务绑定成功。业务提交时验证附件归属、用途、可用状态并建立引用；头像替换后解除旧引用，不能直接删除可能仍被引用的文件。
- 只回收过期且无引用的暂存附件。绑定、删除和清理需锁定/条件更新，防止并发绑定被误删；不沿用扫描所有文件并按 24 小时删除的实现。
- 数据库和磁盘不是同一个事务：上传失败要补偿清理，删除采用可重试的删除状态，失败保留可追踪记录。分批定时清理，不在每次上传中遍历整个目录。
- 分片续传、在线文档预览、公共分享链接、多驱动实现和全局去重不作为首批必需功能。

安全设计参考：[OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)。这里只记录设计依据，不能替代实现后的安全验证。

## 第一批实现边界（历史记录，后续完成情况见下方）

- UploadModule 已独立注册（包括生产环境），当前仅提供策略读取/完整替换，不提供新文件上传或下载接口；现有 Playground 上传保持原样。
- 三张实体表为 `sys_upload_policy`、`sys_attachment`、`sys_attachment_reference`，新表由部署方创建，无迁移、无执行 DDL、无自动初始化策略。管理员先通过策略管理显式配置，缺失用途返回 404、禁用用途在上传服务入口返回 403。
- 策略数据库版本使用 `revision`；缓存使用独立随机 generation 和 Lua 条件回填，60 秒 TTL 从本次查询开始计时，缓存缺失策略同样有 TTL。同进程同用途并发请求合并；不声称具备跨实例单次回源保证。
- 数据库提交后最多尝试三次原子更换 generation 并删除缓存；全部失败则告警并返回说明“已保存”的 503，旧快照最多保留 60 秒，管理员可重试保存。数据库/Redis 之间不提供强一致承诺。
- Redis 读取故障每进程最多每秒发起一次降级回源；仅回填失败也设置一秒熔断窗口。读取不到经过校验的策略返回 503。数据和缓存都无效时不会放行。
- 首批策略资源安全上限为单文件/请求总量 1 GiB、20 个文件、30 天未绑定保留期；实际业务限制全部来自策略行。文件验证器、头像尺寸约束与代理/流式请求限制在上传接入批次实现，当前格式配置不代表旧上传已经支持这些格式。
- 已验证实体 PostgreSQL 元数据、DTO/领域规则、Nest 模块依赖解析、策略缓存及事务调用顺序；真实 PostgreSQL/Redis 约束、Lua 执行和多实例故障仍待集成验证。

## 完成后的实际边界

- 独立 UploadModule 提供上传、附件详情/分页/删除、鉴权下载、受控公开头像、本人头像绑定；新增 `sys_attachment_audit`，共四张新表。Swagger 是字段/端点参考；部署说明在 `docs/modules/attachments.md`。
- 全部 JSON 使用 ResOp；上传 HTTP 200，保留 url 并增加附件 ID/可见性等。私有 url 需认证取 Blob，不能当匿名 img 地址；公开头像需绑定当前用户头像字段。旧用户管理直接更新外部头像 URL 或删除用户时，事务内释放旧引用。
- 文件写入 `var/attachments`，不在 static root；图片受限解码并重编码；Office ZIP 检查主文档/内容类型；文本验证 UTF-8；常见媒体/PDF 进行格式识别。共支持十三种配置格式，不声称格式识别等于杀毒。扫描 provider 默认返回 unscanned，可替换接入部署方引擎。
- 先写 pending 记录再流式存储，完整 multipart/内容验证后提交 ready 状态；提前关闭的 multipart 流立即失败，不等到 120 秒超时。pending 崩溃租期为 15 分钟；后台每分钟检查最多 100 条，引用和到期状态在锁内复核。失败删除保留 deleting 状态重试。
- 服务端注册业务权限处理器并在业务事务内 bind/unbind；不提供任意客户端 businessId 绑定入口。已绑定数据根据业务权限读，管理员通过专门权限读，未知业务默认不赋权。
- 19 组隔离真实 PostgreSQL/Redis/Fastify 集成检查（含 production 环境）验证格式、缓存 Lua、约束、事务回滚、下载权限、公开绑定、并发清理和 Swagger。40 个 Jest 套件/233 个测试及静态/构建/锁定契约检查通过。完整登录/Passport 和浏览器 Vben e2e 仍属于 M8；数据库新表/策略初始化、持久卷、容量/频率限制、病毒扫描由部署按文档配置。
