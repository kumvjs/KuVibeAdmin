# M7 积分与充值前端计划

日期2026-09-30；用户明确追加packages/frontend页面范围，已选择playground复用现有管理页面。此前“仅后端、Vben外部工程”边界在此次追加范围内不再适用；原生iOS/Android客户端仍在仓库外。

## 需求与决策

完整度assumable，Level2：沿用Vue3/Vben/Antdv Next；加入真实后端请求适配，保留其他示例应用。普通用户查看本人可用/冻结积分、完整流水、充值套餐/报价、扫码入口、历史订单/详情/取消/状态恢复。运营管理积分账户/流水/增减/冻结/核销/解冻/冲正；套餐版本/发布/限量/商品映射；活动/首单/优惠预算/发券；订单筛选、退款、对账、用户风险审计。

资金和ID始终用十进制字符串，展示格式使用bigint，不转Number。写入统一使用稳定幂等键；请求超时后的同一操作保留原键，修改内容重新生成；提交期间禁止双击。首单赠分显示预计与实际，不把报价视作保证；删除积分始终为带原因扣减并保留流水。

网页仅发起微信/支付宝扫码。Apple/Google商品由管理端配置，历史订单可以展示，但网页不伪造商店购买或客户端SDK。支付准备轮询与订单状态轮询有上限、可重试、组件离开停止；只有服务端paid显示成功并刷新积分。渠道未配置时呈现真实不可用状态，保留订单恢复/取消入口。

## 实施步骤

1. 接入真实响应/Cookie刷新/后端菜单与权限，移除本应用mock登录默认账号，添加Docker前端开发服务；不修改其他应用。
2. 增补只读订单管理游标筛选接口（userId/status/channel/商户号），沿用订单READ权限；不引入数据库结构变更。
3. 添加用户积分/流水、充值和历史订单页面；顶部提供积分展示与快捷入口。
4. 添加管理积分、套餐/商品、优惠/券、订单/退款/对账/风险页面；权限按后端已有码，不给普通角色资金操作授权。
5. 后端种子增加页面入口并保留已有授权/记录，验证重复初始化与普通用户最小权限。
6. 静态/构建、资金精度与幂等行为测试、真实Docker前后端浏览器验收（含普通用户/403/失败恢复），审查后提交Git并回填证据。

## 验收与约束

权限不足隐藏相关操作并由服务端最终拒绝；未知状态/查询失败不能显示成功或0余额。游标分页没有伪造总页数，分页/加载失败不丢失已显示数据。金额报价过期/库存409提示重新确认，未付订单不加积分，退款和对账必须填写原因。实际渠道缺配置的门槛保持原记录，不将浏览器演示当真实支付。

读取用户已有前端基线，保留上游框架文件和许可证；不升级依赖版本、不全仓格式化。API契约以当前后端Swagger为准，本阶段只增补必要接口。Docker隔离Linux依赖/源码热更新；不覆盖宿主机依赖、密钥或其他项目容器。
